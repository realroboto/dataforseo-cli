# Testing decisions

## Testing Decisions

- A good test drives the CLI from the outside and asserts stdout, stderr, the exit code and the exact requests sent (gapi SPEC:155), plus the Store rows (dfs addition: the Store schema is a contract). It asserts no internals.
- **Seam 1 — `run(argv, io)` in-process**, gapi's seam (34:116; gapi SPEC:155). `io` carries `env` (a temp `DFS_CONFIG_DIR`), `fetch` (fake; real `Response` objects; any unexpected call fails loudly), `stdin`, `stdout`, `stderr` and `sleep` (backoff never waits), like gapi's `Io` type (`google-apis-cli/src/run.ts:33–41`) and its test helper (`google-apis-cli/test/helpers/io.ts:4`). **Agent design:** `io` also takes `now`. Reason: the 12 h reuse window, the 24 h spec and price checks, and `--since` filters need a clock that tests control; gapi seeds times relative to `Date.now()` instead (`google-apis-cli/test/run.test.ts:99`); an injected clock makes the windows exact in tests.
- **Seam 2 — the bin as a real process**: `--help`, `--version`, and two dfs processes that write one Store at once (WAL, busy timeout) (34:124).
- **Seam 3 — `pnpm test:sandbox`**, on the Mac only, real HTTP at cost 0. It sends each request example through `dfs --sandbox` unmodified but for time-bound dates, on the overlaid spec (a 40501 or 40506 on a field the overlay added fails the run), plus the `id_list` hand path with the body of the spec's `serp/id_list` example (31:214), dates moved the same way, collects Standard tasks, and saves to a temp Store. Each run writes a committed file of the paths the sandbox does not cover (40404), with spec SHA and date. A new 40404 or any other error fails the run (34:131–133). **Time-bound dates (#26):** vendor checks some example dates against now, so a fixed example fails once time passes. `id_list` `datetime_from`/`datetime_to` (from at most 1 month back with `include_metadata`, to before now) and `hotel_searches` `check_in`/`check_out` (check_in not before today) move by whole days: `datetime_to` to now − 1 d, `check_in` to now + 7 d; span, format and other values kept. In window, sandbox `id_list` answers 40404 (probe 2026-11-08): coverage file entries. The release runbook requires it (34:132). Reason: open-seo's gzip regression passed stubbed-`fetch` tests; only real HTTP catches transport faults (r34:72–73). **Sandbox fact (probe 2026-11-07):** the sandbox ignores unknown field names (`zz_bogus` → 20000) and checks values only (`depth: "lots"` → 40501; `category_codes` `[10994]` and `["10994"]` both 20000). So this run catches a wrong value or shape on an overlay field, not a wrong field name; vendor docs settle names.
- The Store is real `node:sqlite` in a temp dir, never mocked (34:124).
- Fixtures (34:117–119): sandbox responses recorded on the Mac by `pnpm fixtures:record` (free), cut to a few items, committed. Hand-written cases that the sandbox cannot produce: 40106 partial, 40601/40602 pending, 40203 spend limit, 50401 timeout, real cost above the estimate, connection lost after send.
- Coverage checklist, not a percentage (34:120–124):
  1. Every spec path (565) yields a command and its `--help`; every request example (272) passes `--dry-run` unmodified, on the overlaid spec.
  2. Every exit code 0–6 has at least one test.
  3. Every cost-guard rule: ceiling, unknown price, unbounded price, `--page-all` stop, real cost above the estimate, the `--dry-run` estimate and guard beside a Reuse candidate. `--page-all` stop rules: `test/pages.test.ts` (page-1 refusal, later stop line, unknown price under an explicit ceiling, a page with no cost in its response, price tree refresh before a reused page 1). Real cost above the estimate on a `+run` post: `test/lifecycle.test.ts` "a +run post above its estimate warns after its status line".
  4. Store: save before print, search, failed save and import, a Store that cannot open (Store handle: a read before the send exits 5, nothing sent), a refused task row write (Task ledger: one warning text, sync time kept), two processes at once, `node:sqlite` smoke test.
  5. Defects of epic #32, one Seam 1 test each, red first:
     - B1: `test/price.test.ts` "--no-validate: count, page, priority and extra fields sent as numeric strings read as their numbers", "--no-validate: an unreadable count or page field makes the price unknown; the guard refuses"; `test/pages.test.ts` "--page-all: offset and limit sent as numeric strings page as numbers (--no-validate)".
     - B2: `test/lifecycle.test.ts` "a collect that fails after its retries keeps the task pending, and the report prints; exit 1", "a collect that fails, then succeeds on a later poll: exit 0", "a failed tasks_ready warns, and polling continues", "a post that loses its connection: no later post, no poll, then the report; exit 1"; `test/collect.test.ts` "a network failure on id_list or a collect: the pass goes on and reports; exit 1", "missing credentials during +collect end the command at once: exit 2, no report" (guard, passed before the fix).
     - B3: `test/transport.test.ts` "every request gives up after 130 s; a paid one (Live or Standard) exits 1, no retry" (D10 row: Standard requests time out too), "free call: no answer in 130 s retries on the transient schedule". Deadline: `test/lifecycle.test.ts` "a free request of +run starts no retry after the --wait deadline", "free requests of +run end at the --wait deadline; the last poll gets one 130 s timeout".
     - B4: `test/lifecycle.test.ts` "collects that pass the --wait deadline: the last poll still collects the unlisted own task", "a failed last tasks_ready still runs the direct collects".
     - B5: `test/lifecycle.test.ts` "a collect envelope 40100 exits 2: no further poll, no last poll", "tasks_ready: a 401 sends no further poll and exits 2; another envelope failure warns, polling goes on", "a collect envelope failure, not account, keeps the task pending: exit 1", "a collect envelope failure, then a success on a later poll: exit 0" (guard, passed before the fix); `test/collect.test.ts` "+collect: a collect envelope 40100 exits 2; another envelope failure keeps the task pending, exit 1".
     - B6: `test/store.test.ts` "a store backup that fails after creating its file removes it, so the rerun works; an existing file stays untouched" (Store open fails on a file that is not a database; copy step fails on a 253-byte target name, its journal name passes 255 bytes).
     - B7: `test/call.test.ts` "a body that is not a JSON object shows its HTTP status and an excerpt; 401 keeps the owner remedy" (HTML 502, JSON array, HTML 401); `test/price.test.ts` "a refresh answered by a body that is not a JSON object names the HTTP status".
     - B8: `test/store.test.ts` "--since past the date range exits 3 (too far back); 99999999d still lists" (`100030000d` and a 400-digit age on `list`, `search`, `spend`).
     - B9: `test/pages.test.ts` "--page-all: an invalid body exits 3 before the price tree loads; nothing sent (B9)" (no stored price tree and a login; the fake fetch sees no `user_data` request).
  6. Budget per Output caller (epic #32 D2): stdout + stderr ≤ 9,000 characters, closing line present. Plain call: `test/call.test.ts` "Compact output stops after a whole item within 9,000 characters; --from continues". `--page-all`: `test/pages.test.ts` "--page-all: offset to 10,000, then offset_token; one budget shared by all pages", "--page-all: stops before the page that passes the ceiling; paid pages kept; rerun reuses them". `+run`: `test/lifecycle.test.ts` "+run posts 250 tasks in 3 posts under one guard and collects them", "exit 6 task lines beyond the budget become a task +<n> more line". `+collect`: `test/collect.test.ts` "+collect: collected responses and task lines share the 9,000-character budget; the closing lines print". `store`: `test/call.test.ts` "store list and store sql: stdout and stderr together stay within 9,000 characters; the cut line closes".
- Added by this spec's agent design (each has a test): a fresh clone with the network off passes `pnpm test`, and `dfs --version` shows the snapshot's SHA and date; a sandbox `user_data` response newer than the real one changes neither the price tree nor the 24 h refresh; a pending task of another run in the same `tasks_ready` scope is neither fetched nor printed by `+run`; spend sums `task.cost` once per task and skips sandbox and reuse rows; first `+collect` pass starts at Store creation; dry-run JSON shape and no DataForSEO call; task, cut and outline lines; daily spec check by SHA with ETag 304, 1 h retry after a failed check; Store `user_version` migration; on_page `+run` polls `/v3/on_page/tasks_ready`, collects through `summary/{id}`, and keeps the task pending until `crawl_progress` is `finished`; `+collect` recovers a lost `ai_optimization` id through the hand path, and HTTP 404 from it gives the warning, no exit 1; `spec:check` conditions 4 (a new example fault and an overlay action with no effect both fail), 5, 6 and 7; an overlay target that is not a normalized path fails the load; `--no-validate` sends a body with an unknown field, warns on stderr, and keeps the task-count and Cost guard refusals; `dfs on_page content_parsing` runs the endpoint and `dfs serp google locations us` fills `{country}`; each `dfs …` command in `skills/dfs/SKILL.md` resolves in the Catalog; a `llm_mentions` body with `target: [{"domain": …}]` passes `--dry-run`; the `backlinks/anchors/live` example with `filters` `["anchor","like","%news%"]` and a body with mixed `filters` items (arrays, `and`, a nested group) pass `--dry-run`; 9 top-level filter conditions exit 3 with nothing sent; `spec:check` condition 4 over the snapshot spec with the committed overlay reports 0 faults, and faults without it (86 type plus 5 name in spec `55a4ed0`, check.py); recovered ids of a bare `task_get` level (`keywords_data/google_ads/search_volume`), of `on_page` and of `on_page/lighthouse` collect through the right path, and an unmapped `url` warns with no call; post at cost 0.0006, then `task_get` at 0, then an `id_list` echo of 0.0006: `store spend` sums 0.0006; a body with `null` on a `nullable: true` field passes `--dry-run`, and `null` on a typed field without `nullable` exits 3 with nothing sent; a response larger than the budget at exit 0, and an exit 6 with 100 pending tasks, each print at most 9,000 characters on stdout and stderr together, with a cut line or a `task +<n> more` line; 40200, 40205 and 40206 exit 2.
- CI never uses the network or a DataForSEO login. `spec.yml` (drift check, not CI) reads only the public vendor spec on GitHub. The login never goes to GitHub (34:116, 34:134).
- Prior art: gapi `test/run.test.ts` (seam 1), `test/cli.test.ts` (seam 2), `test/helpers/fetch.ts` (gapi SPEC:155), `test/helpers/io.ts` (`google-apis-cli/test/helpers/io.ts:4`), pruned real fixtures (r34:31).
