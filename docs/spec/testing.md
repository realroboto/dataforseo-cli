# Testing decisions

## Testing Decisions

- A good test drives the CLI from the outside and asserts stdout, stderr, the exit code and the exact requests sent (gapi SPEC:155), plus the Store rows (dfs addition: the Store schema is a contract). It asserts no internals.
- **Seam 1 — `run(argv, io)` in-process**, gapi's seam (34:116; gapi SPEC:155). `io` carries `env` (a temp `DFS_CONFIG_DIR`), `fetch` (fake; real `Response` objects; any unexpected call fails loudly), `stdin`, `stdout`, `stderr` and `sleep` (backoff never waits), like gapi's `Io` type (`google-apis-cli/src/run.ts:33–41`) and its test helper (`google-apis-cli/test/helpers/io.ts:4`). **Agent design:** `io` also takes `now`. Reason: the 12 h reuse window, the 24 h spec and price checks, and `--since` filters need a clock that tests control; gapi seeds times relative to `Date.now()` instead (`google-apis-cli/test/run.test.ts:99`); an injected clock makes the windows exact in tests.
- **Seam 2 — the bin as a real process**: `--help`, `--version`, and two dfs processes that write one Store at once (WAL, busy timeout) (34:124).
- **Seam 3 — `pnpm test:sandbox`**, on the Mac only, real HTTP at cost 0. It sends each request example through `dfs --sandbox` unmodified, on the overlaid spec (a 40501 or 40506 on a field the overlay added fails the run), plus the `id_list` hand path with the body of the spec's `serp/id_list` example (31:214), collects Standard tasks, and saves to a temp Store. Each run writes a committed file of the paths the sandbox does not cover (40404), with spec SHA and date. A new 40404 or any other error fails the run (34:131–133). The release runbook requires it (34:132). Reason: open-seo's gzip regression passed stubbed-`fetch` tests; only real HTTP catches transport faults (r34:72–73). **Sandbox fact (probe 2026-11-07):** the sandbox ignores unknown field names (`zz_bogus` → 20000) and checks values only (`depth: "lots"` → 40501; `category_codes` `[10994]` and `["10994"]` both 20000). So this run catches a wrong value or shape on an overlay field, not a wrong field name; vendor docs settle names.
- The Store is real `node:sqlite` in a temp dir, never mocked (34:124).
- Fixtures (34:117–119): sandbox responses recorded on the Mac by `pnpm fixtures:record` (free), cut to a few items, committed. Hand-written cases that the sandbox cannot produce: 40106 partial, 40601/40602 pending, 40203 spend limit, 50401 timeout, real cost above the estimate, connection lost after send.
- Coverage checklist, not a percentage (34:120–124):
  1. Every spec path (565) yields a command and its `--help`; every request example (272) passes `--dry-run` unmodified, on the overlaid spec.
  2. Every exit code 0–6 has at least one test.
  3. Every cost-guard rule: ceiling, unknown price, unbounded price, `--page-all` stop, real cost above the estimate.
  4. Store: save before print, search, failed save and import, two processes at once, `node:sqlite` smoke test.
- Added by this spec's agent design (each has a test): a fresh clone with the network off passes `pnpm test`, and `dfs --version` shows the snapshot's SHA and date; a sandbox `user_data` response newer than the real one changes neither the price tree nor the 24 h refresh; a pending task of another run in the same `tasks_ready` scope is neither fetched nor printed by `+run`; spend sums `task.cost` once per task and skips sandbox and reuse rows; first `+collect` pass starts at Store creation; dry-run JSON shape and no DataForSEO call; task, cut and outline lines; daily spec check by SHA with ETag 304, 1 h retry after a failed check; Store `user_version` migration; on_page `+run` polls `/v3/on_page/tasks_ready`, collects through `summary/{id}`, and keeps the task pending until `crawl_progress` is `finished`; `+collect` recovers a lost `ai_optimization` id through the hand path, and HTTP 404 from it gives the warning, no exit 1; `spec:check` conditions 4 (a new example fault and an overlay action with no effect both fail), 5, 6 and 7; an overlay target that is not a normalized path fails the load; `--no-validate` sends a body with an unknown field, warns on stderr, and keeps the task-count and Cost guard refusals; `dfs on_page content_parsing` runs the endpoint and `dfs serp google locations us` fills `{country}`; each `dfs …` command in `skills/dfs/SKILL.md` resolves in the Catalog; a `llm_mentions` body with `target: [{"domain": …}]` passes `--dry-run`; the `backlinks/anchors/live` example with `filters` `["anchor","like","%news%"]` and a body with mixed `filters` items (arrays, `and`, a nested group) pass `--dry-run`; 9 top-level filter conditions exit 3 with nothing sent; `spec:check` condition 4 over spec `55a4ed0` with the committed overlay reports 0 faults, and 86 type faults plus 5 name faults without it (check.py); recovered ids of a bare `task_get` level (`keywords_data/google_ads/search_volume`), of `on_page` and of `on_page/lighthouse` collect through the right path, and an unmapped `url` warns with no call; post at cost 0.0006, then `task_get` at 0, then an `id_list` echo of 0.0006: `store spend` sums 0.0006; a body with `null` on a `nullable: true` field passes `--dry-run`, and `null` on a typed field without `nullable` exits 3 with nothing sent; a response larger than the budget at exit 0, and an exit 6 with 100 pending tasks, each print at most 9,000 characters on stdout and stderr together, with a cut line or a `task +<n> more` line; 40200, 40205 and 40206 exit 2.
- CI never uses the network or a DataForSEO login. The login never goes to GitHub (34:116, 34:134).
- Prior art: gapi `test/run.test.ts` (seam 1), `test/cli.test.ts` (seam 2), `test/helpers/fetch.ts` (gapi SPEC:155), `test/helpers/io.ts` (`google-apis-cli/test/helpers/io.ts:4`), pruned real fixtures (r34:31).
