# Pricing module

3. **Pricing** — Estimate (G:47) and Cost guard (G:51).
   - Price tree source: the `price` tree of `GET /v3/appendix/user_data` (free, 6/min), kept in the Store's `price` table with its fetch time (31:107, 31:199). Only a non-sandbox `user_data` response with envelope `status_code` 20000 and a `price` node writes that table. A sandbox or failed response never does: sandbox data is dummy (r34:51). Any such call writes it, including aviato's daily balance read (46:359). **Agent design:** before a paid call, when the tree is older than 24 h and credentials exist, dfs calls `user_data` first. If that refresh fails, dfs uses the older tree and warns. No stored tree counts as older than 24 h. If the refresh fails and no tree exists, the price is unknown.
   - Price rules: dfs's own data, one rule per paid spec path or path pattern. A rule gives the price node, a factor against the node price, the billing unit and the parameter multipliers (31:107; r31:16–22, r31:58–66, r31:92). Reason: node keys do not mirror paths, and one node covers several list prices (r31:16–22).
   - **Agent design (ticket 05):** a rule may name paid body fields (multiply the task price, add base prices, or add a fixed USD per unit) and a count field for `per_result` leaves (else 1). Vendor sources disagree on an extra → higher price. Organic `se_type`: each SERP after the first 25% less (help-center rule; Bing Live `depth` 100 = $0.0155), though pricing-page tables show full price; the real-cost warning flags a miss. Other types and YouTube: full price per page. `serp` and `keywords_data` have no unbounded cost: every multiplier has a published cap.
   - **Agent design (ticket 06):** `dataforseo_labs`, `backlinks`, `domain_analytics` bill per task plus per item (row) returned. Item count: array length or number in a body field (`limit`, `keywords`, `targets`, …), capped at the documented maximum; absent `limit` → API default. Date-range endpoints (backlinks `history`, `timeseries_*`; Labs `historical_rank_overview`; `technology_stats`) count periods from `date_from` (absent: earliest date) to `date_to` (absent: today); `group_range` sets the period. `technology_stats` period undocumented → per day (worst case). `historical_serps`: at most 13 monthly snapshots. Labs `include_clickstream_data: true` → ×2 (docs). `historical_search_volume` has no tree node → `historical_keyword_data` node (same general rate). No unbounded cost in these modules.
   - **Agent design (ticket 07):**
     - On-Page `task_post`: per page, count `max_crawl_pages` (required, no documented maximum). Each paid flag adds coefficient × base per page: `load_resources` 2, `enable_javascript` 9, `enable_browser_rendering` 33 (includes first two), `enable_content_parsing` 1, `calculate_keyword_density` 1 (help-center/cost-of-onpage-api-parameters). Instant Pages, Content Parsing Live: one page per task, same flags. On-Page result paths free.
     - Merchant, App Data, Business Data: per `depth` block, each block full price; block size per path. App Data: Google and Apple share nodes, block sizes differ.
     - My Business Updates: leaf = task fee + first 10 updates; each next block 1/3 of leaf.
     - Extended Reviews: docs multiplier (keyword ×3, `cid`/`place_id` ×2) over pricing-page fixed fee (higher price).
     - Content Analysis trends, LLM Mentions `historical`/`timeseries_*`: periods as ticket 06 (`date_group`, `group_range`).
     - LLM Responses, all models: provider cost known only after run → unbounded. `llm_responses/models` free.
   - Free list: the paths that never charge (`task_get`, `tasks_ready`, `tasks_fixed`, `id_list`, `errors`, `user_data`, `locations`, `languages`, `webhook_resend`, the reference lists `locations_and_languages`, `categories`, `status`, `industries`, `job_functions` (docs: "not be charged"), `available_filters`, `available_history`, `index`, the path `/v3/domain_analytics/technologies/technologies` (docs: "not be charged"), …) (r31:105–109).
   - Estimate = worst case from the body: task count, priority, `depth`, `limit`, `max_crawl_pages`, known multipliers (31:104). **Agent design (ticket 05):** `max_crawl_pages` only lowers the cost (help-center/what-is-max-crawl-pages-and-how-does-it-work), so the serp estimate ignores it. Rounding follows the API (depth rounds up to the billing unit, r31:60).
   - **Vendor fact (help-center/above-100-results-with-serp-api, read 2026-11-07):** Google organic bills per SERP of 10 results; `depth` 15 bills 2 SERPs; each SERP after the first of an Organic `se_type` costs 25% less. `priority: 2` reads the `priority_high` leaf, else `priority_normal`.
   - **Agent design:** a missing tree triggers the refresh, so the first paid call loads it. Reason: a fresh install must not need a manual `user_data` call. `DFS_MAX_COST` sets the ceiling only; it does not unlock an unknown or unbounded price (user story 17). `--dry-run` reads the stored tree, never refreshes.
   - **Agent design:** a rule whose cost has no bound in the body (LLM Responses: provider cost settles after the run, r31:84) is marked unbounded and treated like an unknown price. Reason: the glossary defines the Estimate as worst case (G:47), and an unbounded cost has none.
   - Guard: estimate > ceiling → exit 4, nothing sent. Unknown or unbounded price → exit 4 unless `--max-cost` was given explicitly (31:104–105). `--page-all`: before each next page, dfs adds that page's estimate to the cost so far and stops before the page that would pass the ceiling (31:189). **Agent design (ticket 12):** `--page-all` takes one task on a POST path with `offset`, else exit 3; `+run`/`+collect` refuse it. Page 1 = task as given; next pages add `offset` = start + items so far while below 10,000, then the endpoint's `offset_token`/`search_after_token` from the last response on the unchanged task (help-center/what-is-the-difference-between-the-offset-and-offset_token-parameters: all other fields identical). Stop: no items, fewer items than `limit`, `total_count` reached, a failed page (its exit), or no new token (warning). Cost so far = real cost of pages sent, reused pages $0. Stop line names the rerun: same task, `--max-cost` = cost so far + next page estimate; reuse makes saved pages $0. Body over 1,000 characters (not `@file`) shows as `<the same --body>`. Unknown price under explicit `--max-cost`: stop before the next page once real cost so far ≥ ceiling. Each page is its own Store row and reuse check. `--dry-run` plans page 1 only. **Agent design:** one `+run` is one command, so all its posts share one ceiling. Reason: 31:104 sets the ceiling per command.
   - `--sandbox`: estimate 0, guard not applied. Agent design. Reason: the sandbox never charges (r34:49).
   - After each paid call, dfs stores the estimate and the real `cost`, and warns when the real cost is higher (31:105).
   - Price-tree check on the Mac: a rule that names a missing price node → unknown price for its paths (exit 4 unless explicit) plus a warning naming the rule (34:108).
